# A useful working tool

Validate the task and build the smallest tool that completes it. Keep inputs, outputs, limits, error messages, privacy behavior, and any cost visible. A nonfunctional placeholder is not an acquisition asset.

The public page should explain what the tool does and show an original example. Keep interactive logic in the appropriate client component while the route supplies accurate metadata and useful visible content. Check missing records, invalid inputs, keyboard use, loading/errors, and mobile output. Do not claim a default conversion rate.

Use SoftwareApplication markup only when its properties describe the actual tool. A price of zero requires it to be genuinely free under the stated conditions. Do not invent ratings to meet feature requirements. FAQ schema is not required for discovery.

Acceptance: test representative valid/invalid inputs, verify the promised result, and inspect metadata and canonical. Offer a product next step only when relevant to the completed task; measure sessions and useful actions separately.
