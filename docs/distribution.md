# Distribution and community plan

Goal: help founders use the toolkit, report real problems, and contribute fixes. Stars are a discovery signal, not the product's success metric.

## Channels

| Channel | Route | Status |
|---|---|---|
| GitHub | Public repo, description/topics, contribution guide, useful demos | Release work in progress |
| skills.sh | Real installs via the [Skills CLI](https://skills.sh/docs/faq); no manual submission form | Install command prepared; listing not yet verified |
| SkillsMP | Public SKILL.md repository indexing; see [FAQ](https://skillsmp.com/docs/faq) | Indexing not verified |
| SkillHub | Publish flow at [app/skills](https://www.skillhub.club/app/skills) | Submission pending; account access may be needed |
| ClawHub | Publish after checking current [official registry documentation](https://docs.openclaw.ai/tools/clawhub) | Compatibility and account access not verified |
| Product Hunt | A launch, rather than a skill package marketplace | Launch assets and human account participation needed |
| GitHub Marketplace | Apps and Actions, not a standalone guide/skill | Not eligible as this repository is packaged |

No marketplace acceptance or listing is claimed until verified. No synthetic installs, star exchanges, paid placements, or automatic social posts.

## Ready-to-review launch copy

**Short description**

An open-source toolkit to find what blocks your SaaS on Google and ChatGPT, fix it, and measure your first organic visits.

**Threads/X draft 1 — useful launch**

I turned my SEO + GEO playbook into an open-source toolkit: Foundvia Discovery.

Give it a SaaS URL. It checks discovery blockers and shows the evidence plus what to fix.

No API keys. No paid crawler. No made-up SEO score.

Try it, report what breaks, or contribute a fix:
https://github.com/curetcore/foundvia-discovery

**Draft 2 — concrete lesson**

Blocking GPTBot does not mean you have to block ChatGPT search.

GPTBot is for potential training. OAI-SearchBot is for search discovery.

Foundvia Discovery checks those rules separately, so you can keep your training preference while debugging search access.

**Draft 3 — invite contributions**

I'm building Foundvia Discovery in public.

The most useful contributions right now: real audit edge cases, better fixtures, and corrections backed by official docs.

If you have a SaaS that search engines struggle to find, try the toolkit and show us the evidence. That's how we make it better.

These are proposals; publish only after the owner reviews and approves the actual wording and destination.
