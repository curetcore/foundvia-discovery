# Product brief

O2 direction approved · October 6, 2026.

## The person and the first useful result

A founder has shipped a SaaS but does not know what to improve for organic discovery. They may work with a coding agent and have little SEO experience. Start from their public URL, not an eleven-module menu.

First useful result: one observed blocker, its evidence, an explanation, a scoped next action, and a verification step. A report with no observed blockers is also useful: explain coverage and suggest a customer-focused experiment instead of inventing a problem.

## Promise and boundaries

**Short description:** An open-source toolkit to audit SaaS discovery blockers and plan your first 100 visits from Google and ChatGPT.

The executable helper checks initial HTML, robots rules and one sitemap. It requires Python 3.10+ and does not require an account or API key. It does not execute JavaScript, prove indexing, inspect all pages or establish that a provider can access a site through its CDN. AI judgment depends on the agent and its available tools; the helper's tests do not prove model performance.

“First 100 visits” means measured Google-organic and recognizable ChatGPT-referred sessions, counted separately and then combined using consistent dates. It is a learning target. Search Console clicks, sessions, signups and payments are different measures.

## User journey

| Step | User action | Toolkit result | Verification |
|---|---|---|---|
| 1. Try | Supply a public URL and run the helper | Bounded observations and coverage | Read the URL and actual response evidence |
| 2. Understand | Read the highest-priority finding | Evidence, consequence, confidence and next step | Distinguish observed, inferred and not checked |
| 3. Fix | Give an agent code access and scoped authorization | Proposed or implemented patch | Local checks; deployment and live checks remain separate |
| 4. Launch | Pick one actual customer question | One useful content/distribution experiment | Original evidence, internal links and a clear next action |
| 5. Measure | Supply authorized analytics or use the tracker | Consistent session counts and attribution limits | Fixed dates, filters and conversion event |
| 6. Contribute | Share a reproducible issue or improvement | Maintainer can reproduce and assess it | URL/fixture, expected behavior and relevant evidence |

Public audit alone does not authorize editing, deployment, paid tools or posting. Preserve intentional private pages and the publisher's training policy. Search access and training consent are separate.

## How the open-source project relates to Foundvia

Foundvia Discovery is the runnable, inspectable toolkit. Foundvia.dev is a separate hosted product with its own service availability and terms. Do not suggest that the toolkit provides hosted history, scheduled monitoring, active API/MCP access or a paid subscription. Link the brand without requiring an account for the local audit.

## Success measures

Measure successful first runs, understandable reports, useful fixes, reproducible issues and contributions. Stars and forks measure interest. Do not infer installations from stars or outcomes from downloads. The five-minute first-report experience is an unverified target until timed tests in O4.
